# ITD Pascal R2 — order/lane integrity preregistration

Status: Development/Validation-only secondary replication/integrity slice. This
protocol is independent of the TDI Pascal cost/utility programme and does not
import TDI conclusions into its design. It does not authorize confirmatory or
final evaluation and it does not change ITD V29.18.

## Question

Does exact packed-`u16` Pascal/subset-zeta materialization preserve a 12-gate
Boolean ANF bank when the physical gate lanes and the order of ANF terms are
changed deterministically and then mapped back to the canonical representation?

The primary failure variable is the exact mismatch count. The transformed table
must agree both with a canonical subset-zeta materialization and with an
independent direct-ANF oracle over every assignment in the declared domain.

## Frozen non-final design

- Development: `n=9`, `K=512` assignments.
- Validation: `n=11`, `K=2048` assignments.
- Gate count: 12, packed in one `u16`.
- ANF density: 24 terms per gate.
- Gate-lane maps: identity, reverse, rotate-by-5.
- Term orders: forward and reverse.
- Six cases per split, 12 total, one bounded `integrity_case` work unit each.
- Every case enumerates its full assignment domain.

The affine term generator is fixed in code and rejects duplicate terms. The
constant pattern is fixed. No timing, speedup, memory-efficiency or model-quality
claim is part of R2.

## Integrity and persistence

The implementation uses ITD-30 campaign infrastructure rather than a parallel
provenance system. The protocol and plan have canonical SHA-256 fingerprints.
Generated Development and Validation fixture bytes are hashed and verified before
execution. Each case emits canonical JSON bytes whose SHA-256 is bound into the
case execution record, and the persistent ledger retains complete, interrupted,
blocked or inconclusive states.

A representation mismatch halts the campaign as `INCONCLUSIVE` after persisting
the offending artifact. It is not converted into a successful or negative
result. Tampered source bytes must fail closed before case execution.

## Protected/final boundary

The protocol schema requires a final split identity, so R2 declares only a
sentinel identity named `itd-pascal-protected-final` with no source digest. No
final bytes are generated by this module. Asking the R2 fixture producer for the
final split raises an error. The campaign plan contains Development and
Validation cases only, so no final authorization object is created or consumed.

## Interpretation boundary

A zero-mismatch R2 campaign establishes only representation-order integrity for
the frozen synthetic bank. It does not replicate TDI's operation-cost result,
does not establish Pascal usefulness for a model, and does not authorize any
promotion into SML-GENIUS, SBG, MOR, Delta-KV, context memory or model
architecture. Any such handoff requires a separate prospective protocol owned by
the destination project.
