# ITD-39.0 — SciRust ITD parity qualification

Status: **implementation slice active**

## Existing Rust implementation

SciRust already contains the pure-Rust `scirust-itd` crate. At the repository revision inspected for this bootstrap, the crate is version 0.1.0, dependency-free, deterministic, forbids unsafe code, and exposes operator, structural-signature, transport, geometry, material and canonical-scenario paths.

The standard qualification commands declared by the crate are:

- `cargo test -p scirust-itd`;
- `cargo run -p scirust-itd --example itd_scenarios`.

ITD Research Lab therefore does not create a second Rust implementation.

## Evidence classes

`OracleEvidenceClass` keeps two authorities separate:

1. `HAND_DERIVED_ANALYTICAL` — independent analytical expectations such as zero-field and rigid-rotation invariants;
2. `PYTHON_REGRESSION_SNAPSHOT` — numerical snapshots generated by the frozen Python V29.18 implementation.

A parity contract is invalid unless both evidence classes are present.

## Implementation identity

`ScirustItdImplementationRef` binds the exact Memorithm/scirust revision, crate name/version and the qualification commands. The caller must supply the exact source revision used by a real run.

## Numeric parity

`NumericParityObservation` records expected/observed values plus explicit absolute and relative tolerances. Tolerance acceptance uses a scale-aware `atol + rtol * max(|expected|, |observed|)` rule.

## Interpretation

`ScirustItdParityReport` exposes failed observation identities explicitly.

Even a complete passing report cannot establish:

- physical validity or universality of ITD;
- that regression snapshots are independent mathematical proof;
- promotion of any V30+ research mechanism.

Those are deliberately hard-coded non-authorities.

## Next work

The next Rust slice should emit these observations from an exact SciRust revision into a retained evidence bundle, then hand that bundle to SciRust-Verify for integrity normalization under ITD-39.2.
