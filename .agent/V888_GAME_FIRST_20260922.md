## Proposed first game: Les deux portes

An episode presents binary clues, removes them from observation, inserts a declared
delay and distractors, then asks the agent to select one of two doors according to
a rule cue. The intended challenge is to remember the clues and combine them,
not to control a complex 3D character or parse market charts.

A minimal combined task can be specified as follows:

- show clue A, then remove it;
- insert a preregistered delay with neutral or controlled distracting observations;
- show clue B, then remove it;
- show rule cue R at the decision step; the earlier clues are not shown again;
- let the agent choose door 0 or 1; the exact environment oracle is
  `correct_door = A XOR B XOR R`;
- return training feedback only after the choice. A missing/invalid/timed-out
  choice is an explicit failure, never silently omitted from the denominator.

R=0 means door 1 for different clues; R=1 reverses that correspondence. Inputs,
rule cues, door labels and episode seeds must be counterbalanced so that a constant
choice, a single current cue or episode order cannot supply the answer. This is a
bounded logical task, not evidence of general reasoning by itself.

Before execution, freeze exact event order, delay grid, distractor process,
encoding, scoring, training budget, splits, state-reset policy and primary metric.
The formula and presentation above are the design proposal, not a frozen or
already successful confirmatory experiment.

## Diagnostic ladder

Use three separate conditions with matched observation/compute accounting:

1. Memory only: retain a clue and choose its corresponding door after a delay.
2. Logic only: show all operands at decision time and apply the declared rule.
3. Memory plus logic: hide earlier operands and present the rule at decision time.

Extend later to overwrite/erase memory, rule changes and new rule compositions.
This uses the existing V888-BOOL-1.1 delayed-XOR, 1.2 memory and 1.3 contextual
composition milestones; do not create conflicting milestone numbers or call them
completed because the interface exists. Truth-table oracles remain diagnostics.

## What counts as learning

Record performance before training and on unseen episodes after successive fixed
training budgets. Distinguish readout-only learning from internal weight/threshold
plasticity and from later topology changes. Log the parameters that actually change.
Reset transient state between independent evaluation episodes while preserving the
learned parameters specified by the protocol. Freeze parameter updates during the
standard evaluation; online adaptation belongs in a separately named condition.

Required controls include exact sequential logic, a no-memory/no-reservoir control,
matched recurrent graphs, a frozen-learning control, shuffled training feedback
and a trained-parameter reset. The exact solver receives the same observable
history and reports its memory/compute cost. It does not share private oracle state
with the learner. Encoder, observation payload and decoder must not contain old
clues, hidden targets, the environment RNG seed or an unaccounted history buffer.

Report unseen-episode accuracy versus training examples, failure versus delay,
interference/relearning, seed-level variation and complete memory/event/latency costs.
Separate task success, training benefit and V888-specific topology advantage.
A visually convincing replay alone establishes none of those claims.
